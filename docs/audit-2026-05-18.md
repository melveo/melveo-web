## 🔴 CRITICAL — fix this week

### C1. `devalue` HIGH-severity CVE
Transitive via `astro` + `@astrojs/react`. Sparse-array deserialization DoS.

- **Action:** `bun update` (or `npm update`) — bumps Astro 6.3.2 → 6.3.3 which carries
  the patched devalue. Verify with `bun audit` afterwards.
- **Verify:** `bun pm ls devalue` should show ≥ 5.8.1.

### C2. Lead forms are dead-but-deployed code (582 lines)
`src/components/LeadFormNotify.astro` and `LeadFormPilot.astro` exist with full
validation, fetch-to-worker wiring, accessible markup — but `grep` finds zero
JSX usage in any page or layout. The `/api/lead` worker still accepts only
`type === 'app-notify'`; if `LeadFormPilot` is ever rendered, every submit
returns `400`.

- **Action — pick one:**
  - **Render them** in Landing.astro (currently the "Get in touch" CTA is just
    a `mailto:` link), and extend the worker to accept `type === 'pilot'`.
  - **Delete them** (and the worker handler) to remove 582 lines of untestable
    surface area.
- **Recommendation:** render. The site has no inline lead-capture; only an
  email link. A form would convert better.

### C3. `/api/lead` rate-limit is optional → potentially unlimited
`src/worker.ts:191` returns `false` (= allow) when the `LEAD_RATE_LIMIT` KV
binding is missing. If KV isn't bound in prod, the endpoint accepts unlimited
submissions per IP — abuse vector for the configured Resend / SES costs.

- **Action:**
  - Make KV mandatory (`wrangler.toml` `kv_namespaces`) and fail-closed when
    absent.
  - Better: add **Cloudflare Turnstile** (free, native to Workers) in front of
    the form. Two lines of HTML + one verify-endpoint check.

### C4. No Content-Security-Policy
`public/_headers` has HSTS, X-Frame-Options, Referrer-Policy — but **no CSP**.
Inline scripts (`AnalyticsHead`, JSON-LD, root locale-detect, rotating-word
config) are everywhere, so adding CSP later is hard.

- **Action:** ship CSP in `Content-Security-Policy-Report-Only` mode first.
  Allow `'self' 'unsafe-inline' https://www.googletagmanager.com
  https://static.cloudflareinsights.com https://fonts.googleapis.com
  https://fonts.gstatic.com`. Move inline scripts to nonced or hashed sources
  over the next iteration, then promote to enforce mode.

## 🟡 IMPORTANT — fix this month

### I1. Google Fonts block render
`src/layouts/BaseLayout.astro:134-137` loads Comfortaa + Inter as a
render-blocking `<link rel="stylesheet">`. Estimated LCP cost: 150–300 ms.

- **Action — pick one:**
  - **Self-host** via `@fontsource/inter` + `@fontsource/comfortaa` (~50 KB
    woff2 each, one-time download, no third-party DNS). CSP-friendly.
  - **Async-load** with `<link rel="stylesheet" media="print" onload="this.media='all'">`
    pattern.

### I2. No image dimensions + manual `<img>` everywhere
`ImageGridScrollMorph.astro:138–499` ships raw `<img>` tags without explicit
`width`/`height`. CLS risk on the largest visual section, and no automatic
`srcset` for retina / different viewports.

- **Action:** convert to Astro's `<Image>` component (`@astrojs/image` or the
  built-in `<Image>` from `astro:assets`). Auto-generates srcset, sets
  intrinsic dimensions, lazy-loads by default.

### I3. Below-fold images loaded `eager`
Six images in `ImageGridScrollMorph.astro:138, 172, 200, 253, 281, 314` use
`loading="eager"` even though they're far below the hero — competes with the
hero LCP for network bandwidth.

- **Action:** switch all but the main morph photo to `loading="lazy"`.

### I4. Root `/` meta-refresh + JS redirect is SEO-weak
`src/pages/index.astro:76` uses `<meta http-equiv="refresh" content="0;…">`
plus `window.location.replace()`. Google treats this as a soft 302 at best;
some crawlers index it as a separate page.

- **Action:** add `/  /cs/  302` to `public/_redirects` (Cloudflare native).
  Keep the JS as a progressive enhancement that upgrades en-locale clients to
  `/en/`.

### I5. Hero rotate-cluster overflow risk at narrow widths
At 320 px width the rotating word + cluster combine to a width that wraps
inconsistently. The typewriter caches per character — at the moment of
de-typing it can sit at e.g. `"decisi"` (visible) before erasing to the next
phrase. Not a bug, but worth flagging: the **longest** rotation word is
`"better training"` (15 chars). At 320 px viewport that fits, but very
narrow android browsers (<320 css px) would wrap unattractively.

- **Action:** add a hard `min-width: 0` + `text-overflow: ellipsis` fallback on
  `[data-rotate-word]` for safety; consider tightening rotation words to ≤ 13
  chars each.

### I6. `<header>` lacks `<nav>` landmark
`Landing.astro:55` uses `<header>` directly for nav links. Screen-reader users
get a "header" landmark but no "navigation" landmark.

- **Action:** wrap the two anchors in `<nav aria-label="primary">`.

### I7. Stale dev images committed to repo
Repo root has 30+ screenshot PNGs (`melveo-honeycomb-*.png`, ~25 MB total)
from previous design iterations.

- **Action:** add `*.png` for repo root to `.gitignore` (keep only
  `public/` assets), `git rm` the existing ones.

### I8. Duplicate planning docs ("Finder copy" suffix)
`docs/data-flow-visualization-plan 2.md`, `image-grid-honeycomb-morph-plan 2.md`,
`performance-preserve-visual-plan 2.md` — accidental "2" duplicates.

- **Action:** `git rm` the duplicates. Add to `.gitignore` pattern `* 2.md`
  to prevent recurrence.

### I9. Color contrast on filled cyan CTA
The `.hero-pill--filled` button uses cyan `#00f0ff` background with what
appears to be dark text. Cyan #00f0ff is ~13:1 against dark bg (text on
dark = great), but text on cyan needs verification — likely closer to
4.5:1 threshold.

- **Action:** check with axe-core or manually verify text-on-cyan-background
  contrast meets WCAG AA (4.5:1 for body, 3:1 for large text).

### I10. No prefetch strategy
`astro.config.mjs` doesn't enable Astro's `prefetch` feature. Privacy / Terms /
locale-switcher navigation pays full waterfall every click.

- **Action:** `prefetch: { prefetchAll: false, defaultStrategy: 'hover' }`
  in astro.config.

## Visual responsiveness sweep

Tested at: 375 × 812 (iPhone), 768 × 1024 (iPad portrait), 1024 (iPad
landscape), 1280, 1440 desktops. Findings:

- **375 px (iPhone)** — hero, morph, dataflow, wordscroll, orb, pricing, FAQ,
  contact all flow cleanly. Header + nav fit comfortably. Photo morph (after
  the 09a4f06 fix) snaps cleanly from rectangle to hex via the CSS class
  transition.
- **768–1024 px (iPad)** — no broken layouts visible. Hex grid resizes to the
  smaller honeycomb pattern.
- **1280–1440 px (desktop)** — full landscape morph plays smoothly, all
  sections aligned, no horizontal scroll, no clipped text.
- **Sections without horizontal dividers** (after the f6cdf4d cleanup) flow
  edge-to-edge cleanly. The pure-black backgrounds between punctuation
  sections create a calmer reading rhythm.

**No layout breaks observed at any tested breakpoint** beyond the rotate-word
caveat in I5.
